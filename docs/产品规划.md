# APartner 产品规划 —— 手机协助助手

> 2026-11-01 自 amoolink `apps/android-companion` 拆分立库。
> 愿景:手机侧的协助助手,与 aLink 桌面端深度互联,并自主提供文件管理与跨设备共享能力。

## 一、定位与原则

1. **契约优先**:与桌面端的伴侣协议 v1(`Proto.kt` ↔ amoolink `packages/companion/src/protocol.ts`)逐字节对齐,**已发布的帧格式冻结**;新能力一律走新增 opcode + 版本协商,不修改旧语义。
2. **零外部依赖**:Kotlin 纯手写(mTLS 用平台 API、UI 程序化构建),保持 APK 小、审计面小、国产 ROM 兼容性可控。
3. **一份代码两种角色**:既是 aLink 的伴侣(互联),也是独立的手机工具(文件管理/共享),无桌面端时功能自主可用。

## 二、现状盘点(自 amoolink M5 迁入)

- mTLS + OTP + SAS 配对;免 USB 调试常驻(BootReceiver + FGS connectedDevice + 电池白名单)
- 通知实时同步 + 快捷回复(RemoteInput);按 App 免打扰
- 短信/通讯录读取 + vCard 导出;来电提醒 + 投屏静音
- 剪贴板互发与加密历史(手机→电脑受焦点模型限制为降级可用)
- 传输并行(文件互传走 mTLS 通道)

## 三、路线图

### V1 拆分立库(本次,2026-11-01)
- [x] 独立仓库 + 改名 APartner(包名不变:`com.amoolink.companion`)
- [x] 独立构建链验证(assembleDebug ✓)
- [ ] CI(GitHub Actions:lint + assembleDebug)

### V2 文件管理
- [ ] 手机端:SAF 文件浏览器(程序化 UI),分类视图(图片/视频/音频/文档/安装包),存储占用概览
- [ ] 协议扩展:新增 opcode `FS_LIST` / `FS_STAT` / `FS_READ` / `FS_WRITE`(分块复用现有传输并行机制)
- [] 桌面端(aLink):远程文件面板——浏览手机目录、拖拽上传/下载、右键「发送到手机」
- [ ] 大文件:断点续传、前后台切换存活(FGS)

### V3 共享
- [ ] 注册系统分享目标(ACTION_SEND):其他 App 分享文件/文本 → 可「发到电脑」或「存入 APartner」
- [ ] **LocalSend v2 协议兼容**(2026-10 AirDrop 调研结论的落地路线):
  - 组播发现(224.0.0.167:53317)+ `/api/localsend/v2/prepare-upload|upload|register`
  - 免装互传:任何装了 LocalSend 的设备(iOS/安卓/桌面)可直接互传
- [ ] 二维码网页收发:APartner 起 HTTP 服务 → 任何设备扫码经浏览器上传/下载(iPhone 无 App 互传的现实路径)
- [ ] AirDrop 检测型能力(可选):BLE 扫描感知附近 AirDrop 发送方(研究成果见 amoolink 侧 `awdl-research`;互通在本机 ROM 受 mfg 剥离限制,仅保留检测)

### V4 深化(远期)
- [ ] 多设备配对(一手机对多桌面/一桌面对多手机)
- [ ] 通知聚合与跨设备剪贴板增强
- [ ] Wi-Fi Aware(NAN)直连观察项:iOS 26 第三方 Wi-Fi Aware API 生态成熟后,评估 iOS 版伴侣端(需要 Apple Developer 账号 + entitlement)
- [ ] 自动备份/恢复(联系人、短信、App 列表)

## 四、关键技术研究结论(2026-10/11,存档于 amoolink 平级 `awdl-research/`)

| 结论 | 对 APartner 的影响 |
|---|---|
| Google Quick Share↔AirDrop 互通 = AirDrop 应用层跑标准 Wi-Fi Aware(NAN) | 理论路线存在,但见下行 |
| StepOS(测试机)在固件层剥离第三方 BLE mfg 数据,无 root 无解 | AirDrop 互通降级为「检测型」;主力互传走 LocalSend/网页 |
| NAN 公开 API(attach/publish/subscribe)在国产 ROM 可用 | V4 直连路线保留技术可行性 |
| LocalSend v2 协议全开放(REST + 组播) | V3 采纳为跨平台共享基座 |
